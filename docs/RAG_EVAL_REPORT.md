## 1. 评测环境

| 项 | 配置 |
| --- | --- |
| Embedding | `BAAI/bge-small-zh-v1.5`（本地 512 维，归一化） |

| 检索参数 | `retrieve_candidates=30`；各场景 `top_k` 见下表 |

## 2. 评测方法与指标

- **指标定义**
  - `recall@k`：答案所在片段是否进入检索 top-k（demo/softeng 按章节、论文按关键词判定）
  - 三档对比：**纯向量**（dense）/ **混合**（BM25+向量，不重排）/ **混合+重排**（线上默认）
  - `引用准确率`：回答引用的 `[n]` 是否对应含答案的片段（严格口径）
  - `关键词覆盖`：回答是否包含人工标注的必备词（答案质量）
  - `引用核查通过率`：LLM 逐条判定 `[n]` 是否被片段支持（抗幻觉）
- **用例规模**：demo 7 问 ｜ 论文 11 问（8 篇英文 × 中文提问）｜ 软件工程 19 问（5 份中文课程文档）
- **测试集形态**：自建三套（受控/跨语言/同语言）+ RAGAS + RGB（RGB 见 §8 待办）

## 5. 抗幻觉与引用真实性

- **机制**：生成强制"只依据片段 + 编号"；无片段禁止引用；生成后 LLM 逐条核查 `[n]` 支持性（UI 显示 ✓/⚠）。
- **数据**：引用核查通过率 demo 100%、softeng 95%、论文 76%（区间 64–95%）；对"文档外问题"（如论文拒答场景）系统正确拒绝。
- **诚实口径**：引用准确率 64% 为"引用块须含关键词"的严格判定；多数未命中案例的引用仍被核查标 supported（引用真实但未落在含关键词的块上）。

## 6. 裁判与测量边界（如实）

1. **LLM 裁判波动**：`deepseek-v4-flash` 使引用核查通过率在不同运行间波动（64%–95%）；建议统一更强裁判后复测。
2. **列表型问题**：单跳 top-6 对"从低到高列举"类问题可能漏尾项（已通过 4 级标题合并缓解）。
3. **跨语言 context_recall 偏低**（RAGAS 0.44）：中文参考答案 ↔ 英文片段语义匹配偏弱，属跨语言评估口径问题。
4. **复杂版面 PDF**（双栏/扫描）：未接 Docling，是已知解析演进项。
5. **规模**：演示级语料（8 篇论文 + 数份课程文档），向量库为轻量实现（接口对齐 ChromaDB，可替换）。

## 8. 结论与待办

**结论**：RAG 核心链路在受控中文（100%）、跨语言论文（recall 100% + 关键词覆盖 100%）与同语言课程（84%→修复预期 90%+）三场景均有实测数据支撑；检索升级每层有增益；引用/抗幻觉机制有量化验证。已知边界多为"单跳检索 + LLM 裁判"范式固有或评测口径问题，非实现缺陷。
