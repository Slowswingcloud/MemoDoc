# MemoDoc 演示剧本（答辩现场）

> 目标：4 分钟内讲清「RAG 检索 + 引用高亮 + 跨会话记忆」三个卖点，全程用受控文档，不赌运气。

## 准备工作（提前一晚）

1. `uv run memodoc index data/demo_doc.md`（确保 bge 模型已下载、索引已建好）。
2. 确认 `.env` 里 `DEEPSEEK_API_KEY` 有效，`uv run python app.py` 能启动。
3. 跑一遍 `uv run python tests/eval.py`，把三个数字记下来（答辩要报）。

## 第一幕：索引 + 检索（约 1 分钟）

- 打开 UI，把 `data/demo_doc.md` 拖进上传框，等状态栏显示"已索引 N 块"。
- 讲一句：**"这是索引流——文档经过解析、标题感知分块、本地 embedding，落进自研向量库。"**

## 第二幕：问答 + 引用高亮（约 1.5 分钟）

依次提问（答案是文档里的硬事实，引用必然命中）：

1. `加入极客社需要满足哪些条件？` → 回答出现 `[1]`，右侧来源高亮到"入社条件"。
2. `单次报销的金额上限是多少？` → 回答 `200 元`，来源高亮"报销额度"。
3. `社团的积分有什么用？` → 演示"先结论后细节"的结构。

- 提问 `今天北京天气怎么样？` → 回答 **"文档中没有相关信息"**（这是抗幻觉的亮点，务必演示）。
- 讲一句：**"生成被强制约束为只依据检索片段，编号与来源一一对应。"**
- 补充一句：回答生成后，来源面板出现 **「✓ 已核查」徽标**——引用核查：LLM 逐条验证每个 `[n]` 确实被对应片段支持（若核查失败会标「⚠ 不支持」），构成"生成—溯源—验证"闭环。

## 第三幕：长期记忆（约 1.5 分钟，核心卖点）

1. 说一句带身份的话：`我是大一新生，刚加入极客社。`
2. 右侧记忆面板立即出现 `👤 身份 · 年级 → 大一新生`。
3. 问：`我还需要交会费吗？` → 回答会结合"你是大一新生"给出 `30 元/学期` 的社费。
4. **点「清空对话（保留记忆）」**（模拟新会话），再问：`我适合参加什么活动？` → 它仍然记得"你是大一新生"，这就是**跨会话记忆**。
5. **关闭「使用长期记忆」开关**，重问第 3 步的问题 → 回答变得"不带个人上下文"，形成鲜明对比。这是证明记忆真实生效的最强证据。

## 收尾话术

> "这个项目复现了两个成熟范式的精髓：Kotaemon 的 RAG 链路（混合检索 BM25+向量、交叉编码器重排、引用核查），和 mem0 的'抽取事实 + 向量去重 + 跨会话注入'记忆机制。评测做了三档对比——纯向量 vs 混合检索 vs 混合+重排，召回率从 X% 提升到 100%；引用准确率 Y%、引用核查通过率 Z%。效果没有追求 SOTA，而是用受控文档 + 强制引用把幻觉压到最低，指标是诚实可复现的。"

## 应急预案

- **模型没下下来**：检索自动回退关键词模式，功能仍可演示（状态栏会显示 `keyword-fallback`）。
- **API 出问题**：先把引用高亮 + 记忆面板展示清楚（这部分不依赖 LLM 流式），再说网络问题。
- **时间不够**：砍掉第一幕的上传演示，直接进入"已索引"状态开始问答。
