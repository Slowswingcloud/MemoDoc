# MemoDoc 学习助手 — 产品方案（优化版）

> 定位：面向教育私有化部署的**长线学习助手**。
> 教师上传课件 / 作业 / 往年题形成班级知识库；学生在复习问答中被系统记住薄弱点；
> 教师据此优化教学。数据不出校、引用可追溯、记忆长线积累。

---

## 1. 核心设计决策（本方案与"功能堆叠"式方案的根本区别）

### 1.1 一套知识库，两种视角（不做两套系统）
教师和学生**共享同一个文档库、同一条 RAG + 记忆 pipeline**，角色只决定"看到什么视图、能做什么动作"：

| | 学生端（复习视角） | 教师端（教学视角） |
| --- | --- | --- |
| 共享 | 课件 / 作业题 / 往年题 / 错题（同一份资料） | 同左 |
| 独有动作 | 复习问答（记忆增强）、查看**自己的学习画像** | 资料管理（上传/分类/删除）、课件问答（查漏补缺）、查看**班级薄弱点统计** |
| 技术实现 | 同一 pipeline + 角色 flag（`teacher=True/False`） | 同左 |

→ 合理性：学生和老师面对的是**同一个知识库**，只是消费方式不同。这既符合真实教学场景（资料是班级共有的），也让代码只有一套核心，工作量减半。

### 1.2 记忆机制升级为"学习画像"
现有记忆抽取（身份/偏好）扩展一个事实类型 **`learning`（学习状态）**：

- 例子：`{type: "learning", subject: "薄弱知识点", content: "对『状态图』的绘制掌握不足"}`；
- 学生端：自己的画像卡（薄弱点、常错题型、偏好）；
- 教师端：**聚合**成班级统计（只给"哪些知识点错误率最高"，不暴露单个学生细节——顺带回答数据隐私问题）。

→ 合理性：记忆从"记住你是谁"升级为"记住你学得怎么样"，成为**长线学习**的核心资产，而不是一个 demo 开关。

### 1.3 "教学优化"落到两个可演示动作
空洞的"教学优化"必须可验证，本方案只承诺两件事：
1. **教师对任意课件/试卷提问**（备课自查盲点、快速查知识点出处）；
2. **班级薄弱知识点统计**（基于学生问答中抽取的 learning 事实聚合展示）。

→ 合理性：两个动作都有数据、有界面、可现场演示，评委问"老师具体能干嘛"有明确答案。

## 2. 功能清单

### P0（MVP，约 4–5 天）
- [ ] 文档库分类：上传打标签（`课程 + 类型：课件/作业/往年题/错题`），文档库按分类过滤查看
- [ ] 双角色切换（教师 / 学生视图）
- [ ] 学生端：复习问答（记忆增强检索）+ 学习画像记忆面板
- [ ] 教师端：资料管理 + 课件问答 + 班级薄弱点统计
- [ ] 3 分钟演示剧本

### P1（时间有余再做）
- [ ] 检索质量诊断面板（dense / hybrid / +rerank 三档对比 UI）
- [ ] 引用句子级定位（点击 [n] 高亮源文件具体句子）
- [ ] 会话导出报告（学习总结 / 教师备课记录）

### 明确不做（降低风险）
- ❌ 真登录 / 鉴权 / 多租户 —— 用角色切换演示；答辩说明"接入教育平台时由平台统一认证（SSO），我们预留角色维度"
- ❌ 自动批改 / 成绩管理 —— 独立算法问题，与 RAG 无关，做了会稀释主线
- ❌ 教育平台内嵌插件 —— 远期一句话带过，不实现
- ❌ 多班级隔离 —— 单班级演示；文档元数据已预留 `course` 字段，扩展成本低

## 3. 数据模型增量（很小）

```jsonc
// 文档元数据（现有 source/section 之外新增）
{ "course": "软件工程", "doc_type": "课件" }   // 课件|作业|往年题|错题

// 记忆事实类型（现有 identity/preference 之外新增）
{ "type": "learning", "subject": "薄弱知识点", "content": "对『状态图』掌握不足" }
```

---

## 4. 3 分钟演示剧本

1. **教师端**：上传《软件工程》课件 + 往年题（打标签）→ 文档库按"课程/类型"分类展示；
2. **切学生端**：提问"状态图怎么画？" → 引用课件回答，系统开始记住你的学习状态；
3. **连续问几轮**（含一道错题）→ 学习画像出现"薄弱知识点：状态图 / 需求分析"；
4. **切教师端**：查看班级薄弱点统计（状态图错误率最高）→ "教学优化"落点；
5. **收尾**：引用可追溯、数据本地不出校、记忆长线积累。

---

## 5. 实施计划（5 天 × 4h，每天可验收）

| 天 | 任务 | 验收标准 |
| --- | --- | --- |
| D1 | 文档分类元数据 + 上传打标签 + 文档库分类过滤 | 分类上传/过滤可用 |
| D2 | 双角色切换 + 教师/学生视图骨架 | 一键切换，视图不同 |
| D3 | 学习画像记忆（extractor 加 learning 类型 + 画像面板） | 多轮问答后出现薄弱点画像 |
| D4 | 教师端班级统计（聚合 learning 事实）+ 课件问答 | 统计表/图可用 |
| D5 | 演示剧本打磨 + 诊断面板（可降级） | 完整走一遍剧本 |

**降级预案**：时间不够 → 砍 P1 的"诊断面板"，保剧本；学习画像抽取质量不稳 → 收窄为"知识点名词 + 掌握程度"模板（few-shot 已具备）。

---

## 6. 为什么这个方案"更合理"（相对功能堆叠式）

1. **共享核心**：双角色共用一套 pipeline，工作量≈单角色，但演示价值翻倍；
2. **记忆成主线**：学习画像是学生侧的核心资产，教师侧聚合统计复用同一份数据——一条数据，两种消费；
3. **每个承诺都可验证**：教学优化 = 提问 + 统计，两个可演示动作，无空话；
4. **风险显式化**：明确的"不做"清单（登录/批改/内嵌），把 7 天预算锁在主线；
5. **数据隐私有答案**：班级统计只聚合不暴露个体，顺带回答评委的合规提问。
